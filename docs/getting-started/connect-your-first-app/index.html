Connect your first app

This walk-through assumes you can sign in to the ACR console and have created an app. You will connect one browser app and, optionally, one server.

1. Create an API key​

Open the app, then API keys (sidebar → Configure) → Create API key.

  • Browser app
  • Server
  • Type: Client (publishable)
  • Allowed origins: exact origins only, for example https://shop.example.com or http://localhost:5175. No paths, wildcards or trailing slashes. Up to 20.
  • Optional expiry: never, 30 days, 90 days or 1 year.

You only get an API key. It is safe to ship in front-end code because it works only from the allowed origins.

  • Type: Server

You get an API key and a secret (acr_secret_…). The secret is shown once. Store it in your secret manager or environment immediately. Lose it, and you must rotate the key.

Developers and above can create and rotate keys; revoking needs the admin role.

2. Install the SDK​

The app Overview page contains a SDK setup card with copy-ready snippets for each framework. The essentials:

  • React
  • Plain browser
  • Express
  • NestJS
$Terminal
npm install @lib-acr/react
TSX
import { ACRProvider } from '@lib-acr/react';

createRoot(document.getElementById('root')!).render(
  <ACRProvider
    config={{
      apiKey: import.meta.env.VITE_ACR_API_KEY,
      endpoint: import.meta.env.VITE_ACR_ENDPOINT, // https://api.applicationcontrolroom.com/v1
      appVersion: '1.0.0',
    }}
  >
    <App />
  </ACRProvider>,
);
$Terminal
npm install @lib-acr/browser
TypeScript
import { BrowserACR } from '@lib-acr/browser';

const acr = new BrowserACR({
  apiKey: 'acr_live_…',
  endpoint: 'https://api.applicationcontrolroom.com/v1',
  appVersion: '1.0.0',
});
acr.start();
$Terminal
npm install @lib-acr/node @lib-acr/express
TypeScript
import express from 'express';
import { ACR } from '@lib-acr/node';
import { ACRMiddleware, ACRErrorHandler } from '@lib-acr/express';

const acr = new ACR({
  apiKey: process.env.ACR_API_KEY!,
  apiSecret: process.env.ACR_API_SECRET!,
  endpoint: process.env.ACR_ENDPOINT!, // https://api.applicationcontrolroom.com/v1
});
acr.startHeartbeat();
acr.flushOnExit();

const app = express();
app.use(ACRMiddleware({ client: acr }));
// ... your routes ...
app.use(ACRErrorHandler({ client: acr }));
$Terminal
npm install @lib-acr/nestjs
TypeScript
@Module({
  imports: [
    ACRModule.forRoot({
      apiKey: process.env.ACR_API_KEY!,
      apiSecret: process.env.ACR_API_SECRET!,
      endpoint: process.env.ACR_ENDPOINT!,
      appVersion: '1.0.0',
    }),
  ],
})
export class AppModule {}
Never put a secret in a browser bundle

Browser SDKs reject an apiSecret at runtime, and TypeScript refuses it at compile time. If a secret ever reaches a browser, rotate that key immediately.

3. Watch data arrive​

  1. Load your app in a browser. Within seconds the app Overview shows SDK connection → Connected and Live visitors now goes to 1.
  2. Analytics shows the visitor with browser, OS, device and, if configured, country.
  3. Events lists session_start, page_view and web_vitals.
  4. Track something of your own and look for it:
TypeScript
acr.trackEvent('checkout_started', { cartSize: 3 });
  1. Throw a test error:
TypeScript
acr.captureError(new Error('first test error'), { handled: true });

It appears under Errors, grouped into one issue with its stack trace.

Why is nothing showing?

Go through Troubleshooting: the most common causes are a missing or wrong allowed origin on a client key, endpoint missing the /v1 suffix, an ad blocker, and Do Not Track (the browser SDK honours it by default).

4. Try remote control​

Open Controls and, with your app open in a browser:

  • turn Maintenance on – the SDK shows a full-page maintenance screen within about a minute;
  • publish an announcement – a banner appears;
  • create a feature flag new-checkout at 50% and read it with acr.flag('new-checkout', false).
