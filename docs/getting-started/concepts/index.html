Core concepts

App​

An app is one deployment target you monitor and control. People reach an app as members with a role: owner, admin, developer or viewer.

  • Production and staging are separate apps. Each has its own API keys, members, telemetry and controls.
  • stage (production, staging, development, other) is a label. It decides the API key prefix (acr_live_ for production, acr_test_ for everything else) and is shown in the ACR console. It does not change behaviour.
  • framework (react, angular, node, express, nestjs, other) and type (frontend, backend, fullstack, microservice, worker, mobile) describe what the app is. The overview page uses them to suggest the right SDK.
  • Apps can be archived (read-only for developers and viewers; SDK requests answer 403 APP_ARCHIVED) and restored, or deleted (all its API keys are revoked at once).
  • Every app has a connection status: pending (no data yet), connected, inactive (nothing received for 5 minutes) or error (ACR could not store a batch).

Member and role​

People reach an app only through membership. Each membership has one role:

RoleCan
viewerRead everything: telemetry, controls, flags, members, key list
developerViewer + create and rotate API keys, create and edit feature flags
adminDeveloper + app settings, archive and restore, members and invitations, controls, announcements, commands, revoke keys
ownerAdmin + delete the app, transfer ownership, grant or remove the owner role

An app always has at least one owner. New members join only through invitations. The role matrix is on Roles and permissions.

API key (credential)​

A credential belongs to exactly one app. There are two kinds:

server keyclient (publishable) key
Valuesacr_live_… / acr_test_… key and acr_secret_… secretKey only
Runs inBack-end processesBrowsers and mobile apps
Proven byThe secret (stored only as a peppered HMAC)The request Origin, which must be in the key's allowed origins
ShownSecret is displayed once, at creation or rotationKey can be viewed again

A browser SDK refuses to be configured with a secret. See API keys.

Telemetry​

SDKs send four kinds of items to POST /v1/ingest/{kind}:

KindMeaningExamples
eventsSomething happenedpage_view, session_start, http_request, your own checkout_started
logsA log line with a level (debug … fatal)payment widget failed
errorsAn exception with a stack traceTypeError: Cannot read properties of undefined
heartbeatA server process is aliveCPU, memory, event loop, GC figures

Items carry attributes: a flat object of strings, numbers, booleans and nulls. Data is kept for the app's plan retention (30 days on the default Free plan, never more than TELEMETRY_RETENTION_DAYS); heartbeats for HEARTBEAT_RETENTION_DAYS (7). See Plan and usage.

Visitor, session, user​

TermWhat it isWhere it lives
VisitorOne browser, identified by a random anonymousIdlocalStorage['acr.anonymousId']
SessionOne stretch of activity in a tab; a new one starts after 30 minutes of inactivitysessionStorage['acr.session']
UserYour own user id, set with identify('user_42'). Use opaque ids, never e-mail addressesMemory only

Server-side events have no visitor, so they are left out of visitor figures.

Control snapshot​

Everything you configure under Controls and Flags is delivered to SDKs as one revisioned JSON document at GET /v1/sdk/config:

  • sdk – kill switch, sample rate, minimum log level
  • maintenance – on/off, message, who is exempt
  • release – latest and minimum version, prompt or force
  • announcement – the one live banner
  • flags – every feature flag with rollout rules
  • commands – active one-shot commands (clear cache, reload)

SDKs check for a new snapshot about once a minute and only download it when something changed. Flags are evaluated inside the SDK, so reading a flag never makes a request. See Remote controls.

Account, device and session (ACR console sign-in)​

Do not confuse these with the telemetry terms above. Signing in to the ACR console involves:

  • an account (user) with a verified e-mail and optional phone and password,
  • a registered device, the browser you sign in from,
  • a session that keeps you signed in on that device until you sign out or it expires.

Details are in Accounts and sign-in.
