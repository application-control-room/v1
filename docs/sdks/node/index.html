@lib-acr/node

The Node.js client: everything in @lib-acr/core, plus runtime heartbeats (CPU, memory, event loop, GC), capture of uncaught exceptions and unhandled rejections, and a flush on exit. It needs a server key and secret and Node.js 18.17 or newer.

$Terminal
npm install @lib-acr/node

Quick start​

TypeScript
import { ACR } from '@lib-acr/node';

const acr = new ACR({
  apiKey: process.env.ACR_API_KEY!,
  apiSecret: process.env.ACR_API_SECRET!,
  endpoint: 'https://acr.example.com/v1',
  environment: 'production',
  appVersion: '1.0.0',
});

acr.startHeartbeat();           // runtime snapshot every 30 s
acr.captureProcessErrors();     // flush then exit(1) on uncaught exceptions (when no other handler exists)
acr.flushOnExit();              // flush once the event loop empties

acr.trackEvent('order_created', { orderId: '123' }, { userId: 'user_42' });
acr.log('info', 'order created', { orderId: '123' });
acr.captureError(new Error('payment declined'), { handled: true });

const enabled = acr.flag('new-checkout', false, { userId: 'user_42' });

Extra options​

All common options plus:

OptionDefaultNotes
instanceId<hostname>:<pid>Identifies this process in heartbeats and on the Performance page
heartbeatIntervalMs30 000At least 1000

Methods you will use​

MethodPurpose
trackEvent(name, attributes?, { userId, sessionId, traceId, … })Record an event
log(level, message, attributes?, { source, … })Record a log line
captureError(error, { handled, source, route, … })Record an exception (never sampled)
heartbeat(options)Send a heartbeat by hand
startHeartbeat() / stopHeartbeat()Periodic runtime heartbeats. While disabled (locally or by the kill switch) none are sent, and they resume when enabled
runtimeSnapshot()Current runtime figures without sending
captureProcessErrors({ exitOnUncaughtException, exitTimeoutMs })Report process-level errors. Exits with code 1 after flushing when this SDK is the only handler. Defaults: exit true, wait 2000 ms
flushOnExit()Flush when the event loop empties
flush() / shutdown(timeoutMs)Flush now; stop timers and flush with a bounded wait
flag(key, fallback, { userId }) / flags({ userId })Evaluate flags
getControlState(), onControlChange(fn), refreshControl()Read maintenance and other state
setEnabled(bool), identify, stats()Control and diagnostics

Heartbeats​

Heartbeats go to POST /ingest/heartbeat. Each carries instanceId, uptimeSeconds and the runtime snapshot as attributes: cpuPercent, rssBytes, heapUsedBytes, heapTotalBytes, externalBytes, eventLoopUtilization, eventLoopDelayP99Ms, gcCount, activeHandles. They drive Runtime instances on the Performance page and the app's Connected / Inactive status.

Flags on a server​

A server process has no "current user", so pass the request's user id:

TypeScript
acr.flag('new-checkout', false, { userId: req.user?.id });

Without a user id only flags rolled out to 100% serve their value; partial rollouts serve the default.

Remote control​

The client polls the control snapshot with the server key. Its timers are unref'd so they never keep the process alive, and shutdown() stops them. The kill switch pauses collection, flushing and heartbeats. For maintenance, use maintenanceMiddleware from @lib-acr/express or ACRMaintenanceGuard from @lib-acr/nestjs, or read acr.getControlState() yourself and answer with the shape from maintenanceResponse() (503 { error: "MAINTENANCE", message, endsAt } plus Retry-After).

Shutdown​

TypeScript
process.on('SIGTERM', async () => {
  await acr.shutdown(2000);   // flush with a bounded wait, stop timers
  process.exit(0);
});
